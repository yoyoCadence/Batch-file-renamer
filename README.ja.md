# Batch File Renamer PWA

[繁體中文](README.md) | [English](README.en.md) | **日本語**

プレビューしてから実行する、ローカルファイル向けの一括リネームツールです。  
旧 PowerShell ユーティリティを静的 PWA として作り直し、大量のファイル名変更という危険な操作を、実行前に確認できる流れへ変えています。

## すぐ使う

Live App: https://yoyocadence.github.io/Batch-file-renamer/

こんな場面に向いています：

- 写真、PDF、スキャン、帳票、エクスポートファイルをまとめて整理する。
- セグメント、文字範囲、固定値、連番、削除、行ごとのリストで名前を作る。
- 実ファイルを変更する前に、すべての結果を表で確認する。
- 1 つのテンプレートファイルを出力フォルダーへ複製し、それぞれ別名で保存する。

## 安心して使える理由

一括リネームで怖いのは、クリックした瞬間に何が起きるか見えないことです。このアプリは重要な判断を画面上に出します：

- **実行できるかを最初に明示**：ファイルを読み込んだ時点で「名前変更を実行できます」か「プレビュー専用」かを表示します。ルールを組んでから全行が実行不可だと気づく、ということがありません。
- **何が変わるか見える**：プレビューは置換された部分と追加された部分をインラインで色分けします。2 列を目で見比べる必要はありません。
- **編集に追従**：ルールを変更するとプレビューが自動更新され、各ルールカードにも before → after が表示されます。
- **OK 行だけ実行**：警告、エラー、重複、変更なしの行は実行対象から分けて表示します。
- **止まった行の理由がわかる**：ブロックされた行には平易な理由が付き、機械的に直せるものはワンクリック修正を提供します。
- **モードが明確**：名前変更は元の場所でファイル名を変更します。コピーはテンプレートを出力先へ複製してから名前を変えます。
- **システムファイルを除外**：`desktop.ini`、`Thumbs.db` などの一般的なシステムファイルや一時ファイルを読み込み時に除外します。

## 主な機能

**処理するファイルを選ぶ**

- Chromium の File System Access API を使ったローカルフォルダーの直接リネーム。
- 処理範囲フィルター：件数付きの拡張子チップと、名前に含む／含まないの条件。現在の条件は 1 文にまとめて表示されます。
- 除外されたファイルも一覧に残り、淡色表示になります（消えたのではなく外したと分かるように）。

**名前の変え方を決める**

- 初心者向けルール：接頭辞・接尾辞の追加、拡張子の変更、クリーンアップ（空白整理、空白をアンダースコアに、特殊文字削除、連続する区切り文字の統合）。
- 応用ルール：セグメント、文字範囲、検索置換（正規表現も可）、大文字小文字変換。
- 値モード：固定値（`{yyyy-MM-dd}` などの日付トークン対応）、リスト、昇順、降順、削除。
- ルールは個別に有効/無効を切り替えられ、ドラッグで並べ替えできます。各カードに before → after を表示します。
- ルールセットは名前を付けて保存・読み込み・削除でき、最後に使ったルールは自動的に記憶されます。

**確認してから実行**

- プレビュー表：インライン差分、件数付きステータスチップによる絞り込み、検索欄、変更後ファイル名の編集。
- ワンクリック修正：連番付与、使用不可文字の置換、Windows 予約名の回避、末尾のドット・空白の削除。
- 一括除外：チェックした行を実行対象から外せます。
- 直前の名前変更バッチを取り消せます。行単位の実行ログ CSV も出力できます。
- CSV インポート/エクスポートによる手動確認や表計算ソフト連携。

**外観**

- UI 言語：繁體中文、简体中文、English、日本語。
- 20 種以上の高精細背景テンプレートと 20 種以上のカラーテーマ。
- 高精細マスコット、シンプル図形版、漫画風ふきだし、ドラッグ反応、自然な移動モードを持つペット助手。

## 使い方の流れ

1. **元を選ぶ**：実際に名前を変更できるのは「元フォルダーを選択」で読み込んだ場合だけです。「ファイルを選択」とドラッグ＆ドロップはプレビュー専用です。
2. **範囲を絞る**：拡張子と名前の条件で、触ってはいけないファイルを対象から外します。
3. **ルールを作る**：上から順に適用され、各カードが効果をその場で表示します。
4. **プレビューを確認**：自動更新されます。「再チェック（ディスク照合）」を押すと、出力先に既に存在する名前も検出します。
5. **OK 行だけ実行**：それ以外の行はそのまま残ります。

## ペットシステム

現在の新しい移動システムの試作は **どこでもドア書類修理屋** です。画面をただ漂うのではなく、自然な移動をします：

- 床やパネルの端を歩きます。
- 別の場所へ移動するとき、どこでもドア、竹コプター、ロープの演出を使います。
- ドラッグ中は驚いた表情の held ポーズになります。
- セリフは、一方的な質問ではなく、短い付き添いの言葉として書き直しています。

従来の自由に漂う移動も、設定から選べます。

## 技術詳細

バックエンド不要の静的 PWA です：

- `pwa/index.html`：メイン UI 構造。
- `pwa/assets/app.js`：アプリ状態、ファイル選択、処理範囲、ライブプレビュー、実行、設定、ペット挙動。
- `pwa/assets/rules.js`：ファイル名ルールエンジン、範囲フィルター、名前の差分、行の修正、CSV 変換、プレビュー行の検証。UI 言語に依存しない純粋なロジックです。
- `pwa/assets/settings.js`：言語、テンプレート、テーマ、ペット、ルールプリセットと直前セッションの保存、翻訳辞書。
- `pwa/assets/style.css`：レスポンシブレイアウト、テーマ変数、背景テンプレート、ペットアニメーション。
- `pwa/service-worker.js`：PWA の runtime cache。cache-first のため、**キャッシュ対象ファイルを変更したら必ず `CACHE_NAME` を更新**しないと再訪ユーザーには届きません。更新が検出されると切り替えを案内します。
- `tests/*.test.mjs`：Node test runner によるルールエンジン、i18n、保存、静的素材、UI 配線のテスト。
- `tests/e2e/*.spec.mjs`：Playwright が Chromium で公開ファイルを実際に操作します。

データの保持：

- バックエンドもデータベースもありません。元ファイル、フォルダー権限、プレビュー行はメモリ上のみで、リロードすると失われます（ファイルハンドルは保存できません）。
- `localStorage` に保存するのは 3 つだけです：外観設定、名前付きルールプリセット、直前のルール／値リスト／モード。
- 処理範囲フィルターと除外行は意図的に保存しません。別のフォルダーに持ち越されて実行内容が黙って変わることを防ぐためです。

ファイル操作の方針：

- 直接リネーム/コピー実行は File System Access API に依存するため、Chromium 系ブラウザーが最適です。
- この API がないブラウザーでも、ルール作成、プレビュー、CSV インポート、CSV エクスポートは使えます。
- ブラウザーのフォルダー選択画面は権限ダイアログであり、ファイル内容ではなくフォルダーだけを表示する場合があります。個別ファイルを選ぶ場合は **Select files** を使ってください。

## ローカル実行

```powershell
py -m http.server 4173 --directory pwa
```

開く：

```text
http://127.0.0.1:4173/index.html
```

## 検証

```powershell
npm run test       # ユニット/静的チェック
npm run test:e2e   # Playwright によるブラウザー検証
```

現在のテスト対象：

- ルールエンジン、範囲フィルター、名前の差分、行の修正、プレビュー行の検証。
- ルール正規化：保存から読み戻した壊れたデータや旧版データでアプリが壊れないこと。
- 設定・ルールプリセット・セッション保存の往復（壊れたデータや書き込み拒否を含む）。
- 4 言語間の翻訳キー一致。
- 20 種以上の背景テンプレートとテーマ、高精細背景素材のサイズしきい値。
- ペット素材、自然移動 hook、service worker cache のバージョン。
- テキストファイル内の未解決 merge marker チェック。
- Playwright：ライブプレビュー、範囲フィルター、差分とワンクリック修正、ルールプリセット、一括除外、実行と取り消しまでの一連の流れ。
